# Covariate fixed-rule estimate

`analysis/with_covariates/3c.1b heldout confirmation.qmd` now uses `run_half_estimate(..., with_covariates=TRUE)`. The filename is retained; the title and interpretation are half-B gain estimates. The same decision, strict |z| > 2, missing-kept policy, assignment and two pre-specified sensitivities are transferred unchanged. Covariate predictions and pre-treatment diagnostics are never substituted with their no-covariate counterparts.

`aggregate_predictive_A` gained configurable main-fit directory and filename prefix, with the original no-covariate defaults preserved. Thus covariate reconstruction uses `data/simulation/wcov/wcov_imputation_*.rds` with identical event-window, predictive-noise, seed, interval and aggregate formulas. `R/heldout_covariate_input.R` creates only the requested half snapshot from all 18 saved checkpoints, selects assigned IDs before computation, and converts paired inclusive tails to mid-p using the existing formula. It never creates a new assignment, fits models, or prepares the other half automatically.

The covariate dry-run project is `_output/heldout/with_covariates/confirmation/render_A/`; refresh its qmd copy from the maintained source before rerendering. Its outputs and logs are isolated from all no-covariate results. Covariate A provides the matching full-precision reference for covariate B; `no_cov_A` summary columns retain the original A values behind the decision. Comparing adjusted A to unadjusted A is descriptive, not a numerical-reproduction test. The shared no-covariate code's numerical reproduction checks remain in their original dry-run outputs.

Explicitly rendering the covariate report with `half: B` supplies authorization through `authorize_B=TRUE`; no hidden marker is required. Direct R engine calls default to `authorize_B=FALSE` and remain guarded unless authorization is explicitly supplied (or previously recorded in the legacy marker). The engine verifies the committed decision bytes and the covariate A decision/assignment hashes before opening any B input. The initial update evaluated A only. A subsequent explicit user B render authorized the B estimate.
